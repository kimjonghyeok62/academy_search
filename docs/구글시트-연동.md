# 구글시트·Apps Script 연동 지도

이 저장소만 봐서는 데이터가 어디서 오고 어디에 저장되는지 알 수 없다. **Apps Script 소스는 이
저장소에 없다** — 별도 저장소에 있고 clasp 으로 올린다. 열 하나 늘리는 일에 세 곳을 함께
고쳐야 하므로 여기에 적어 둔다.

## 흐름

```
브라우저 (Vite/React, src/)
      │  fetch('/api/…')
      ▼
Vercel 서버리스 (api/)
      ├─ api/sns-probe.js ──────→ 네이버 (검색·플레이스·블로그) : 조사만, 저장 안 함
      └─ api/apps-script-proxy.js ─→ Apps Script 웹앱 /exec ──→ 스프레드시트
```

프록시가 따로 있는 이유는 브라우저에서 Apps Script 를 직접 부르면 CORS 에 걸리기 때문이다.
POST 는 `text/plain` 으로 넘겨야 Apps Script 가 `postData.contents` 로 받는다.

## SNS게시점검 시트에 열을 하나 늘릴 때

열 이름 목록이 **세 곳**에 있고 순서·이름이 같아야 한다.

1. **Apps Script** (`Code.js`)
   - `SNS_HEADERS` 배열 **맨 뒤에** 추가한다. 뒤에 붙여야 `_snsSheet()` 의 “기존 열이 모두 새
     헤더에 있는가” 검사를 통과해, `_snsMigrate()` 가 **숨김 백업 시트를 만들고 값을 살린 채**
     열을 늘린다. 중간에 끼우면 그 검사에는 걸리지 않지만 굳이 위험을 살 이유가 없다.
   - 사람이 적는 열이면 `var SNS_XXX_COL = SNS_HEADERS.indexOf('이름');` 을 두고,
     `_webSaveSnsChecks` 의 보존 블록에 `if (row[SNS_XXX_COL] === '') row[…] = existing[at][…];`
     한 줄을 더한다.
2. **프런트** (`src/utils/snsCheck.js`)
   - `SNS_COLUMNS` 맨 뒤에 추가
   - 화면 값을 실어 보내야 하면 `PASSTHROUGH` 에 추가
   - 자동 조사가 화면에서 지우면 안 되는 값이면 `KEEP_KEYS` 에도 추가
3. **올리고 배포**

   ```bash
   cd "C:/Users/bro33/coding/AppsScript-academy-inspection/appsscript" && clasp push --force
   ```

   `clasp push` 만으로는 `/exec` 가 바뀌지 **않는다** — 웹앱은 배포된 판을 서빙한다.
   같은 URL 을 갱신해야 하므로 새로 배포하지 말고 기존 배포 ID 를 지정한다.

   ```bash
   cd "C:/Users/bro33/coding/AppsScript-academy-inspection/appsscript" && clasp list-deployments
   ```

   `@N - 설명` 이 붙은 것들 중 프런트가 쓰는 ID(위 표의 `/exec` 주소에 든 것)를 골라:

   ```bash
   cd "C:/Users/bro33/coding/AppsScript-academy-inspection/appsscript" && clasp deploy --deploymentId "<그 ID>" --description "무엇을 바꿨는지"
   ```

   URL 이 바뀌면 `api/apps-script-proxy.js` 와 `src/utils/inspectionSheets.js` 두 곳을 함께 고쳐야 한다.
4. **확인** — 마이그레이션은 배포 뒤 첫 요청 때 일어난다.

   ```bash
   curl -sL "<exec 주소>?action=getSnsChecks" | head -c 400
   ```

   첫 행의 키에 새 열 이름이 보이고 행 수가 그대로면 된 것이다. 시트에는
   `SNS게시점검_백업_yyyyMMdd_HHmmss` 숨김 탭이 하나 생긴다.

## 빈 값은 “안 넘어온 것”이다

`_webSaveSnsChecks` 는 사람이 적는 열(`비고`·`연락처`·`수동확인`·`플레이스지정`·`묶음`·`적요`)에
빈 문자열이 오면 **기존 값을 지킨다.** 자동 조사 결과에는 이 값들이 없어서, 그대로 쓰면 담당자가
적어둔 것이 조사할 때마다 지워지기 때문이다.

그래서 **지우기는 빈 문자열로 안 된다.** 지웠다는 사실을 값으로 보내야 한다.

- `플레이스지정` → `'-'` (`PIN_CLEARED`)
- `적요` → `'-'` (`MEMO_CLEARED`, 화면에서는 빈 칸으로 보인다)
- `수동확인` → `'{}'` (빈 JSON 객체)

## 시트 열을 새로 만들지 않고 값을 넣는 자리

`수동확인` 열은 JSON 문자열이라, `__` 로 시작하는 예약 키를 넣으면 Apps Script 를 고치지 않고도
행마다 값을 남길 수 있다 (칸 키는 언제나 `${열}|${항목}` 형태라 부딪히지 않는다).

- `__done` — 확인 마감 시각
- `__noplace` — 네이버플레이스가 아예 없다고 사람이 확인해 준 시각

**사람이 시트를 열어 읽고 고쳐야 하는 값은 이렇게 넣지 않는다** — JSON 안에 있으면 시트에서는
못 읽는다. `적요` 를 예약 키가 아니라 진짜 열로 만든 이유가 그것이다.
