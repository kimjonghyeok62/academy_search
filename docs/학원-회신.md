# 학원 회신 — 고쳤다고 학원이 알려 오는 길

안내 문자는 한쪽으로만 흘렀다. 보내고 5일을 기다린 뒤 **1,000곳(학원 755 · 교습소 314)을
통째로 다시 조사해야** 누가 고쳤는지 알 수 있었고, 2일 만에 고친 학원도 5일이 지나야 마감됐다.
문자를 언제 보냈는지가 어디에도 없어 '기한이 지난 무응답' 목록조차 만들 수 없었다.

이제 문자 끝에 **그 학원만 여는 주소**가 한 줄 들어간다. 학원이 눌러 고친 항목을 표시하면
시트에 남고, 담당자는 **회신이 온 곳만** 다시 조사해 마감한다.

```
https://<도메인>/r/a1003-7k2xq9      ← 회신 (고쳤다고 알려 오는 곳)
https://<도메인>/g/a1003-7k2xq9      ← 교습비 게시표 예시 (참고)
                └┬┘└─┬─┘ └──┬─┘
                 │   │      └ 서명 6자 (HMAC-SHA256 을 36진수로)
                 │   └ 등록(신고)번호
                 └ a=학원, h=교습소
```

두 화면은 **같은 토큰**을 쓴다. 길만 다르므로 서명 장치가 하나로 끝난다.

## 왜 구글폼이 아닌가

프리필(`?usp=pp_url&entry.xxx=값`)은 된다. 그런데 프리필 값은 학원이 지울 수 있고 자유
텍스트라 **명칭·번호 표기가 흔들린다** — 회신을 학원에 도로 붙이는 일이 다시 손일이 된다.
폼은 정적이라 '그 학원에 지적된 항목만' 보여줄 수 없어 모든 매체×항목을 늘어놓게 되고,
응답이 별도 시트로 떨어져 `SNS게시점검` 과 다시 맞춰야 한다. 파일 첨부에는 구글 로그인이
따라붙어 증거사진도 받지 못한다.

**토큰이 학원을 특정하므로 학원은 이름도 번호도 입력하지 않는다** — 오기가 생길 자리가 없다.

## 흐름

1. **담당자** — 점검표가 결과를 읽은 뒤 `/api/reply-link` 로 **모든 행의 주소를 한 번에** 받아
   `Map` 으로 들고 있는다 (행마다 부르면 750번 왕복한다).
2. `✉ 문자` 를 누르면 그 주소가 들어간 문구가 복사되고, 같은 순간 **`발송일시`** 가 시트에 남는다.
3. **학원** — 주소를 열면 `GET /api/reply?t=…` 가 그 행을 읽어 오고, 화면은 문자와 **같은 함수**
   (`noticeItems`)로 같은 목록을 그린다. 항목마다 `수정했습니다 / 아직입니다 / 저희 매체가 아닙니다`.
4. 보내면 `POST /api/reply` 가 **`회신일시`·`회신내용` 두 칸만** 쓴다.
5. **담당자** — 점검표의 `회신옴` 칩으로 그곳만 골라 `↻` 로 다시 조사하고, 회신 열의
   `처리` 를 눌러 본 것으로 표시한 뒤 마감한다. `기한초과` 칩이 곧 확인서·처분으로 넘어갈 목록이다.

회신은 **판정을 바꾸지 않는다.** '학원이 그렇게 말했다' 는 사실일 뿐이고, 이행 여부를 정하는
것은 언제나 다시 조사한 결과다. 화면도 그렇게 말한다.

## 시트에 늘어난 열 셋

| 열 | 누가 쓰나 | 비어 있다는 뜻 |
|---|---|---|
| `발송일시` | 담당자 화면 (문자 복사할 때) | 아직 안 보냄 |
| `회신일시` | 학원 (`saveSnsReply`) | **무응답** |
| `회신내용` | 학원 | — |

`회신내용`은 **사람이 읽는 한 줄**이다 (`플레이스 번호 수정함 · 블로그 교습비 아직 | "다음 주에
올리겠습니다"`). JSON 으로 넣지 않는 이유는 담당자가 시트를 열어 그대로 읽어야 하기
때문이다 (`구글시트-연동.md` 의 마지막 절과 같은 규칙). 기계가 판단할 것 — '회신이 왔는가' —
은 `회신일시` 한 칸으로 충분하다.

`발송일시`는 **문자를 만든 때**다. 실제 발송 시각이 아니고, 화면에도 그렇게 적어 두었다.
복사 뒤 문자마당에 붙여넣는 흐름이라 실무상 근사치로 쓴다.

## 회신 칩 — 다섯 자리가 곧 진행 상황

```
미발송 ──▶ 대기중 ──▶ 기한초과        (확인서·처분으로)
                └──▶ 회신옴 ──▶ 회신처리
```

서로 겹치지 않고 합이 전체라, 칩에 붙은 숫자를 그대로 읽으면 지금 어디까지 왔는지 보인다
(`replyStage`). 기한 일수는 `⚙ 문자 설정` 의 값을 그대로 쓴다 — 문자에 적어 보낸 기한과
화면이 세는 기한이 다르면 안 된다.

**`회신옴` 은 '아직 담당자가 보지 않은 회신' 이다.** 회신이 왔다는 것과 담당자가 그것을 보고
처리했다는 것은 다른 사실이라, 섞어 두면 회신이 쌓일수록 '무엇을 봐야 하는지' 를 알 수 없다.
회신 열의 `처리` 를 누르면 `회신처리` 로 넘어가고 초록이 걷힌다 (`__replyseen`, 수동확인 JSON).

마감(`확인` 열)과는 또 다른 축이다 — **`처리` 는 '이 회신을 봤다', 마감은 '이 학원을 다 봤다'.**

### ↺ 초기화 — 복사가 곧 발송은 아니다

`✉ 문자` 를 눌러 문구를 복사하면 `발송일시` 가 남지만, 시험 삼아 눌러 본 것일 수도 있다.
그대로 두면 기한초과 목록이 부풀어 **보내지도 않은 학원이 확인서 대상이 된다.**
회신 열의 `↺ 초기화` 가 `발송일시`·`회신일시`·`회신내용`·`__replyseen` 을 한 번에 지운다
(한 번 묻는다). 조사 결과와 O/X 는 건드리지 않는다.

지우는 값은 빈 문자열이 아니라 **`'-'`(`REPLY_CLEARED`)** 다 — 빈 값은 Apps Script 가
'안 넘어온 것' 으로 보고 기존 값을 지키므로 영영 지워지지 않는다 (`PIN_CLEARED`·`MEMO_CLEARED`
와 같은 규약). 읽는 쪽(`sentAt`·`repliedAt`·`replyText`)이 `'-'` 를 빈 값으로 되돌린다.

## 교습비 게시표 예시 (`/g/<토큰>`)

'교습비를 게시하라' 고만 하면 무엇을 어떤 모양으로 붙여야 하는지 모른다. 신고된 내용으로
만든 게시표를 보여 주면 그대로 인쇄해 붙이거나 보고 따라 만들 수 있다. 내부용(학원 안)과
외부용(옥외가격표시) 둘 다 있고, 담당자 화면이 쓰던 **같은 함수**로 만든다.

자료는 마스터 스프레드시트에서 온다. 브라우저가 직접 읽지 않는 이유는 마스터 CSV 가 몇 MB 라
휴대폰에 통째로 내려보낼 수 없어서다 — `api/reply-form.js` 가 그 학원의 줄만 골라 준다
(`masterSheet.js`, 5분 캐시). 회신 화면(`GET /api/reply`)과 나누어 둔 것도 같은 이유다.

게시표 HTML 에는 새 창용 단추 줄(`.print-bar`)이 붙어 있다. 화면 안에 끼워 보여줄 때는
**걷어낸다**(`stripPrintBar`) — CSS 로 가리는 것만으로는 부족하다. 워드는 HTML 을 자기 문서로
바꿀 때 `display:none` 을 지키지 않아 '🖨️ 인쇄 / ✕ 닫기' 가 파일에 그대로 들어간다.
만드는 함수(`buildTuitionFormHtml`)는 담당자 화면과 함께 쓰므로 손대지 않는다.

### 세 가지로 받을 수 있다

| 무엇 | 어떻게 만드나 | 쓰는 자리 |
|---|---|---|
| **PDF** | 브라우저 인쇄 → '대상을 PDF로 저장' | 그대로 인쇄해 붙일 것 |
| **JPG** | `html2canvas` 로 `.page` 마다 한 장 (2배 크기) | 문자·카카오톡·블로그 |
| **DOCX** | 표를 WordprocessingML 로 직접 쓴다 | 학원이 고쳐 쓸 것 |

셋 다 재료는 **같은 HTML 하나**다. 양식을 두 벌 만들면 화면과 파일이 조금씩 달라져도
아무도 모른다. 무거운 것(`jszip` 97KB·`html2canvas` 201KB)은 **누를 때** 불러온다 —
열자마자 쓰지도 않을 것을 휴대폰에 내려받게 할 수 없다. 같은 이유로 `file-saver` 도 쓰지 않고
여섯 줄짜리 `download()` 를 둔다.

### DOCX 는 표를 직접 쓴다 — altChunk 를 쓰지 말 것

처음에는 `altChunk` 로 만들었다. HTML 을 통째로 docx 안에 넣어 두면 **여는 쪽이** 표로
바꿔 주는 방식이라 코드가 스무 줄이면 끝났고, MS 워드에서는 잘 열렸다.
**한워드(한컴)에서 열면 빈 문서가 나온다.** altChunk 를 모르는 프로그램은 그 부분을 통째로
건너뛰는데, 건너뛰면 남는 것이 없기 때문이다. 실제로 한워드로 열어 확인했다 — 옛 파일은
`표 0개 · 글자 0자`, 새 파일은 `표 1개 · 글자 639자`.

학원이 무엇으로 열지 우리는 고를 수 없다. 그래서 [htmlToDocx.js](../src/utils/htmlToDocx.js) 가
`<w:tbl>` 을 직접 쓴다. **CSS 를 다시 해석하지는 않는다** — 게시표는 이미 iframe 안에
그려져 있으므로, 그 DOM 에서 `getComputedStyle` 과 `getBoundingClientRect` 로 실제 값(칸 너비·
줄 높이·테두리 굵기·배경·가운데맞춤)을 읽어 옮긴다. 브라우저가 이미 한 계산을 두 번 하지 않고,
화면과 파일이 어긋날 자리도 없앤다. 그래서 `downloadFormDocx` 는 HTML 문자열이 아니라
**iframe** 을 받는다 (JPG 와 같다).

옮길 때 걸리는 것 둘:

- **rowspan 이 워드에 없다.** 세로로 이어 붙일 칸을 줄마다 두고 첫 칸에 `vMerge restart`,
  아래 칸에 `vMerge` 를 준다. HTML 의 줄을 그대로 옮길 수 없어 먼저 격자를 세운다 —
  내려오는 rowspan 을 자리에 앉힌 뒤, 그 줄의 칸을 남은 자리에 차례로 넣는다.
- **줄 높이를 그려진 그대로 넣는다**(`trHeight hRule="atLeast"`). 워드가 제 나름대로 다시
  잡으면 한 장짜리가 두 장이 된다. 실제로 altChunk 때는 내부용이 두 쪽으로 나뉘었고,
  지금은 MS 워드·한워드 모두 **한 쪽**이다.

`styles.xml` 은 없어도 열리지만 넣는다. 없으면 프로그램마다 제 기본값(줄간격·10.5pt 등)을
얹어 표가 늘어난다.

## 지켜야 하는 규칙

**1. 문자와 회신 화면이 같은 목록을 낸다.** 둘 다 `noticeItems(result)` 를 부른다. 그래서
`noticeItems` 는 문구 모듈이 아니라 `snsCheck.js` 에 있다 — 회신 화면이 휴대폰에서 열리는
자리라 문자 조립 코드(대조창·게시표까지 딸려온다)를 함께 내려받게 할 수 없다.

**2. 학원에게 담당자 자료가 새면 안 된다.** `api/reply.js` 의 `PUBLIC_FIELDS` 에 **적은 열만**
나간다. `연락처`(원장 휴대폰)·`비고`·`적요`·`묶음`·`플레이스지정`은 빠져 있다. 보내는 것을
고르는 방식이라 **시트에 열이 늘어도 저절로 새 나가지 않는다.**

**3. 회신을 `saveSnsChecks` 로 쓰면 안 된다.** `_webSaveSnsChecks` 는 보존 목록 밖의 열을 빈
문자열로 덮는다 — 성긴 레코드를 보내면 `판정`·`채널상세`가 통째로 날아간다. 그래서 회신은
두 칸만 건드리는 `saveSnsReply` 를 따로 둔다.

**4. 새 열 셋은 보존 목록에 있어야 한다.** 없으면 담당자가 O/X 칸 하나를 누를 때마다 학원
회신이 지워진다 (`Code.js` 의 `SNS_SENT_COL`·`SNS_REPLY_AT_COL`·`SNS_REPLY_COL`).

**5. 회신 안내 블록은 길이를 줄일 때도 남긴다.** 문자가 LMS 한도를 넘으면 ①게시표 예시
②매체 3곳 ③교습과정 차례로 덜지만, 회신 블록은 어느 단계에서도 덜지 않는다 — 이 문자를
보내는 목적이 여기 있다. 게시표는 참고 자료라 가장 먼저 덜어낸다.
(회신 블록 138바이트, 게시표 블록 157바이트쯤)

**6. 회신 두 칸을 평소에 실어 보내지 않는다.** 화면이 들고 있는 옛 값이 방금 들어온 학원
회신을 덮기 때문이다. 예외는 지울 때 — `resultToRecord` 가 `'-'` 일 때만 그 두 칸을 얹는다.

| `PUBLIC_BASE_URL` | 로컬에서만 | 앱(5173)과 함수(3000)의 포트가 달라 링크에 앱 쪽을 일러 줄 때. 배포에서는 비워 둔다 (요청 헤더의 host 를 쓴다) |

## 로컬에서 확인하는 법

`vercel dev` 없이 회신 화면만 보려면 가짜 서버 하나면 된다 — `/api/reply` 에 시트 행 하나를
돌려주고, `/api/reply-link` 에 서명한 주소를 돌려주면 화면이 그대로 돈다.

1. `SNS_REPLY_SECRET=아무값 node <가짜서버>` → 3000 포트
2. `npm run dev` → 5173 (`vite --port …` 로 옮겨도 된다. `.claude/launch.json` 에는 5174 로 적혀 있다)
3. 토큰은 이렇게 만든다:
   ```bash
   SNS_REPLY_SECRET=아무값 node --input-type=module -e "import {signReplyToken} from './api/_lib/replyToken.js'; console.log(signReplyToken('학원','1003'))"
   ```
4. `http://localhost:5173/r/<그 토큰>` 을 **시크릿 창**으로 연다 (로그인 없이 열려야 한다).
   토큰 한 글자를 바꾼 주소는 거부되어야 한다.
5. 문구만 확인할 때는 화면을 거치지 않아도 된다 —
   `buildNoticeSms(target, result, academy, { replyUrl })` 를 콘솔에서 바로 부를 수 있다.

## 함정

**배포 뒤 첫 요청까지 열이 늘지 않는다.** `_snsMigrate` 는 `_snsSheet()` 가 헤더 차이를
발견할 때 돈다. 재배포만 하고 아무도 부르지 않으면 시트는 그대로다.

**`clasp push` 만으로는 `/exec` 가 안 바뀐다.** 기존 배포 ID 로 다시 배포해야 한다
(`구글시트-연동.md` 참고). 그러지 않으면 화면은 새 코드를, 웹앱은 옛 코드를 본다.

**회신이 온 곳도 다시 조사해야 한다.** `회신옴` 은 '학원이 그렇게 말했다' 이지 '이행' 이 아니다.
칩으로 골라 `↻` 를 눌러 확인한 뒤 마감할 것.

**같은 링크는 계속 열린다.** 만료를 두지 않았다 — 기한이 지난 뒤라도 고쳤다고 알려 오는 편이
이롭고, 늦었다는 사실은 `발송일시`·`회신일시` 두 칸이 이미 말한다. 다시 보내면 앞의 회신을 대신한다.
